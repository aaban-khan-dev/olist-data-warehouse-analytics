# Data Quality Log — Olist Data Warehouse

This document records the data quality issues identified during source data profiling, their impact on analytical reporting, and the mitigation strategies implemented during warehouse development.

| # | Data Quality Issue | Evidence | Business Impact | Mitigation |
|---|--------------------|----------|-----------------|------------|
| 1 | `customer_id` is not a stable customer identifier | `customer_id` has 99,441 distinct values, while `customer_unique_id` has 96,096 distinct values. | Customer-level analyses such as RFM and retention would treat repeat customers as new customers. | Use `customer_unique_id` as the business key for the Customer dimension. |
| 2 | Multiple geolocation records exist for the same ZIP code prefix | 1,000,163 geolocation records map to only 19,015 unique ZIP code prefixes. | Direct joins would create duplicate records and inflate analytical results. | Deduplicate records to a single representative location when building `dim_geography`. |
| 3 | Orders without customer reviews | 768 orders have no associated review. | Review-based reporting would contain missing dimension references. | Load unmatched records using the Unknown member (`-1`) during ETL. |
| 4 | Order without payment record | One order has no corresponding payment information. | Payment analysis would contain an orphaned transaction. | Load the record using the Unknown member and flag it for data quality reporting. |
| 5 | Missing product category translations | Two product categories do not have English translations. | Product reporting would contain null category values. | Map missing translations to an Unknown category during transformation. |
| 6 | Reviews are not strictly one-to-one with orders | Duplicate `review_id` values and multiple reviews exist for some orders. | Review metrics may be duplicated if joined directly to orders. | Retain a single review per order during transformation using the defined business rule. |
| 7 | Missing delivery timestamps | Delivery timestamps are absent for canceled and unavailable orders. | Delivery duration calculations would produce incorrect results. | Restrict delivery performance analysis to delivered orders only. |
| 8 | Source schema contains inconsistent column names | Product dimension includes source columns such as `product_name_lenght`. | Reduces readability and maintainability of downstream models. | Rename columns during transformation while preserving the original staging schema. |
| 9 | Incomplete time periods | Early 2016 and the final months of 2018 contain very few transactions. | Time-series analyses may be distorted by partial reporting periods. | Restrict trend analysis to the representative period (January 2017 – August 2018). |
| 10 | Non-delivered orders cannot participate in delivery analysis | Approximately 3% of orders were canceled, unavailable, or otherwise undelivered. | Transit time and delivery delay metrics would be inaccurate if all orders were included. | Build delivery KPIs using delivered orders only. |
| 11 | Products with missing/untranslated category | 624 products → category_en = 'unknown' | Null category names in dim_product | COALESCE to 'unknown' fallback |
